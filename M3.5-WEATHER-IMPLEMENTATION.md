# M3.5 — Step 2: Weather Simulation

## Overview

Implemented a functional weather simulation in the existing 3D workspace with three presets: Sunny, Cloudy, and Rainy. The feature adds a collapsible Weather section to the inspector with selectable presets that update the Three.js scene lighting in real time, without affecting solar position, shadow camera, or energy calculations.

## Files Created

### `frontend/src/lib/3d/lighting.ts`
- **`WeatherPreset`** type: `"sunny" | "cloudy" | "rainy"`
- **`WEATHER_ADJUSTMENTS`** record with per-preset factors for sun intensity, ambient intensity, hemisphere intensity, and sun color shift
- **`applyWeatherPreset()`** function — called after `applySunToScene()` each frame; modifies only existing light properties (intensity, color) — does NOT create new lights, move the sun, or alter shadow camera settings

## Weather Preset Behavior

| Preset | Sun Intensity | Ambient Intensity | Hemisphere Intensity | Sun Color Shift |
|--------|--------------|-------------------|---------------------|-----------------|
| **Sunny** (baseline) | 1.0× (full) | 1.0× (full) | 1.0× (full) | 0 (no shift) |
| **Cloudy** | 0.7× (softer) | 1.15× (fill) | 1.05× (fill) | −0.15 (cooler) |
| **Rainy** | 0.65× (reduced) | 1.2× (fill) | 1.1× (fill) | −0.25 (cooler) |

- **Intensity**: The sun's directional light intensity is multiplied by the preset factor *after* `applySunToScene()` sets the elevation-dependent value. This preserves the sun's natural elevation cycle (sunrise → solar noon → sunset) while applying the weather adjustment on top.
- **Color**: The sun's RGB channels are shifted slightly cooler for cloudy/rainy presets. The shift is applied on top of the solar-driven color (`sunColorHex()`), so the change is always reversible when returning to Sunny.
- **Ambient/Hemisphere**: Fill intensities are increased slightly to maintain visibility while reducing direct light.
- **No particle systems**: The "Rainy" preset uses only a color tint — no rain particles, no accumulated event listeners, no new Three.js objects.

## Reversibility

- Switching **Sunny → Cloudy → Sunny** restores the exact same lighting state. The multiplication approach (`sun.intensity *= factor`) ensures that returning to Sunny exactly cancels the previous adjustment, because `applySunToScene()` resets the elevation-based intensity each frame and the factor of 1.0 has no effect.
- No lights are created or destroyed. No event listeners are added. The scene graph is unchanged.
- Switching between Cloudy and Rainy similarly restores the previous state without residue.

## Systems Left Untouched

- **Sun position** (azimuth/elevation) — completely driven by pvlib via the shared `SunClock`, unchanged
- **Shadow camera** — configuration and parameters unchanged
- **PVGIS/PVWatts energy calculations** — weather preset has no effect; analytical pipeline is separate from visual preset
- **Panel placement, setbacks, obstacle collision** — geometry validation unchanged
- **Building mesh, obstacle meshes, panel meshes** — not recreated or modified
- **Date/time controls** — fully preserved
- **X-ray mode, Reset View, stage progression** — all preserved
- **Existing backend wake/autostop architecture** — no additional API requests introduced

## Known Limitations

- No actual rain particles or precipitation visual effects (constraint: "do not accumulate lights, materials, particle systems, or event listeners")
- Color shifts are subtle (RGB channel modulation), not a full scene recoloration
- Weather preset affects only the directional light + ambient/hemisphere fill; it does not alter satellite imagery, terrain, or any other scene element
